\chapter{Storage and Retrieval}\label{ch:storage}
In \autoref{sec:dual}, many of the methods discussed employ a dual architecture where one of the modules is somehow responsible for retaining previous experiences, often termed the `knowledge base'.\ It was also mentioned that the general idea of using a knowledge base might be shared amongst many lifelong learning techniques, but the implementation varies wildly between them.\ A knowledge base does not always consist of a single module, but can have a complex architecture in and of itself; something akin to a library where the knowledge is stored, and a librarian who can organize and retrieve the knowledge correctly.

This chapter will aim to provide an overview of the many different shapes and forms such libraries can take, as well as the manner in which librarians might keep them organized.


\section{Knowledge bases}\label{sec:KB}
In this section, a brief overview on the type of knowledge that is stored (e.g., a policy itself, state transitions), and the form in which they are stored (e.g., tuples, abstract representations).

In \textcite{Nguyen2011}, the authors use Gaussian process regression to learn an inverse dynamic model (\autoref{sec:DM}).\ Since they want the model to incrementally learn in realtime, they limit themselves to a fixed budget of data points, represented as vectors $\bvec{d}_i$, to use for updating the model.\ These data points are stored in a dictionary $\mathcal{D} = \{\bvec{d}_{i}\}_{i=1}^m$ which is incrementally updated with the aim to be as informative as possible (\autoref{sec:retrieval},~\ref{sec:KB-maintainance}).\ The contents of a point $\bvec{d}_i$ are largely dependent on the application.\ Since \textcite{Nguyen2011} are trying to fit a model for a regression task, they opt for vectors of the form $\bvec{d} = [\bvec{x}\ \bvec{y}]^T$, where $\bvec{x}$ is simply the input vector and $\bvec{y}$ are the target values.

In \autoref{sec:expansions} it was mentioned that \textcite{Chatzilygeroudis2016} created a map of atomic behaviors an agent might execute.\ This map is created using Map-elites~\cite{Mouret2015}, an algorithm that can set up a knowledge base containing many descriptions of solutions and recording their performance according to a specified performance measure.\ The knowledge base is represented by a discretized space of $N$ user-defined dimensions.\ These dimensions define a feature-space of interest within a potentially huge or even infinite search space.\ The paper provides a conceptual example: ``MAP-Elites could search in the space of all possible robot designs (a very high dimensional space) to find the fastest robot (a performance criterion) for each combination of height and weight''~\cite{Mouret2015}.\ It can be noted that ``search'' can be interpreted as ``store'' in the context of the algorithm.\ The \emph{description} of a solution can be stored in any way that suits the application, the performance metric is stored as a function.\ \textcite{Chatzilygeroudis2016} provide a toy example for an agent that can move in 2D space using a preset step size; the \emph{description} of the behavior here is thus a single value $\theta$ that gives the direction of the step.\ The evaluation metric in this case is the \emph{Generic Reward} of the behavior (\autoref{sec:expansions}), namely two Gaussian processes describing the relative position of the agent after executing the behavior.

To accomplish a good performance over several different classification tasks, \textcite{Aljundi2016} train multiple models: one per task.\ These models, termed `Experts', are stored in the knowledge base, in a manner most fitting for the model type (e.g., a FNN as layer architectures with corresponding weights and biases).\ The purpose of this knowledge base is to identify a fitting model for a given task and only selectively load this model into memory.\ Furthermore, when a new task is encountered, the most relevant `Expert' can be loaded in to function as a prior for training a new `Expert'.

As described in \autoref{sec:dual}, \textcite{Sprechmann2018} introduce memory-based parameter adaptation, where a memory module $M$ provides context to a network $g_\theta$, allowing it to appropriately adapt its parameters for better performance.\ This memory contains key-value pairs $(h_j,\,v_j)$, obtained during training and given by the embedding networks output and the training labels, respectively, i.e., $h_j = f_{\gamma}(x_j)$ and $v_j = y_j$.\ This means that the keys are represented by abstract feature vectors, the values are dependent on the task (e,g., one-hot encoded class labels for classification, target values for regression), and memory $M$ is thus a higher-dimensional space spanned by these keys and values.\

\textcite{Schwarz2018} use a knowledge base in the form of a separate policy $\pi_{KB}$.\ This policy would thus be a neural network and is obtained through knowledge distillation\todo{citation needed?}, a process where the outputs of one model are used as labels to train a second model.\ Active policies can reference the knowledge base to accelerate learning (\autoref{sec:retrieval}).\ When it is time to store a newly learned policy $\pi_t$, the outputs of the knowledge base's policy $\pi^{KB}_{t+1}$ are trained to approximate the outputs of the active policy $\pi$, whilst also referencing $\pi^{KB}_{t}$ to prevent drastic forgetting of old policies (\autoref{sec:KB-maintainance}).\

The knowledge base in \textcite{Wang2022} stores a potentially infinite number of pairwise parameters $(\bvec{\theta},\,\bvec{\vartheta})$, where $\bvec{\theta}$ are the policy parameters, and $\bvec{\vartheta}$ represents the parametrized environment.\ \added{These pairs are assigned to an environment cluster $M^{(l)}$,} \replaced{the purpose being}{.\ The purpose of this library is} to recognize the most similar environment model compared to the one currently encountered, and to use the corresponding policy parameters as a strong initial policy to fine-tune (\autoref{sec:retrieval}).\ The form of the policy parameters $\bvec{\theta}$ again depends on the form of the policy itself.\ The environments, however, can be parametrized as models by training the reward function $r = g^1_{\bvec{\vartheta}}(s, a)$ and the state transition function $s' = g^2_{\bvec{\vartheta}}(s, a)$ and concatenating them to obtain $[r, s'] = g_{\bvec{\vartheta}}(s, a)$.\ An environment model $g_{\bvec{\vartheta}}$ can be trained on sequences of state-action pairs to produce corresponding reward-state sequences, and the corresponding parameters $\bvec{\vartheta}$ are stored alongside $\bvec{\theta}$ in the library.\

In \textcite{Xie2021}, previous experiences are stored in the form of tuples $(\bvec{s, a, s'}, r)$.\ These tuples are stored in a replay buffer $\mathcal{D}^i$ for each task $\mathcal{T}^i$.\ For \emph{all} tasks, each replay buffer is stored; they will serve to provide offline data for pretraining an agent when learning a new task (\autoref{sec:retrieval}).

Similar to \textcite{Schwarz2018}, the authors in \textcite{Shin2017} do not store knowledge explicitly in a buffer or library, but rather use a separate model to fulfill this function.\ However, contrary to \textcite{Schwarz2018}, the model is not a policy but a generative model trained to imitate training data from previous tasks.\ The generative model used in this case uses a Generative Adversarial Network (GAN) architecture.\ These models have a dual architecture of their own, where a generating model is trained to optimize producing outputs that can \emph{fool} a discriminator, which is in turn trained to optimize distinguishing real data from generated data.\ These two networks are trained in parallel and compete against each other (hence, adversarial) to obtain the best result.


\section{Retrieval and Detecting Distributional Shifts}\label{sec:retrieval}
Storing knowledge is not very useful in and of itself.\ To properly exploit the advantages of using a knowledge base, knowledge needs to be retrieved.\ This encompasses recognizing what might be relevant knowledge given new observations, using the knowledge base to detect when an agent is `breaking new ground' in the data landscape, or the manner in which all information in the knowledge base generally can be used to inform an agent.

Dictionary $\mathcal{D}$ in \textcite{Nguyen2011} is simply used as a selective representation of the training data to fit the model using Gaussian process regression, and, being dynamically updated (\autoref{sec:KB-maintainance}), thus informs the model by providing it with the most informative data points.\ However, a technique used to measure the informativeness of a point touches on detecting a distributional shift.\ The authors use a linear independence test to check whether a potentially new datapoint $\bvec{d}_i$ can be approximated in the space spanned by all the vectors $\{\bvec{d}_j\}_{1}^{i-1}$.\ The measure $\delta$ is the distance from point $\bvec{d}_i$ to the (hyper-)plane $\{\bvec{d}_1,\,\dots,\bvec{d}_{i-1}\}$.\ A predetermined threshold can then be used to decide whether point $\bvec{d}_i$ relates to a distributional shift.

In the context of pure MAP-elites from \textcite{Mouret2015}, a stored solution is retrieved by querying the specific features of interest.\ The authors call their method an \emph{illumination} algorithm, rather than a search algorithm, since MAP-elites does not search for a single optimum, but instead `illuminates' the best solutions in the defined feature space.\ In \textcite{Chatzilygeroudis2016}, the behavior performance-map (created using MAP-elites) is searched using Bayesian Optimisation\todo{citation needed?}.\ Bayesian Optimisation uses the Gaussian processes that predict the \emph{Generic Rewards} as its prior distribution and employs the Upper Confidence Bound (UCB)\todo{citation needed?} function as its acquisition function to guide the selection process, balancing exploration and exploitation.\ The key addition to this method is that the acquisition function does not directly evaluate the prior distribution's Gaussian processes, but rather the reward function, provided by the \emph{reward selection layer}, of those Gaussian processes.

The manner in which the collection of experts in \textcite{Aljundi2016} is used is twofold.\ During training, the most relevant expert is selected as a prior for the new model by measuring task relatedness.\ At test time, the collection of experts is simply used to select the best expert for the task at hand.\ To measure task relatedness without having to store all the training data of previous tasks, the authors train an auto-encoder\todo{requires footnote?} network $A_k$ alongside each expert.\ This auto-encoder learns an abstract representation of task data, where important nuances in the task's characteristics can be more accentuated.\ The reconstruction error between the validation data $D_k$ of a task $T_k$ and a previous auto-encoder's $A_a$ reproduction is used to measure how well $T_k$ resembles $T_a$.\ The expert corresponding to the most related task is selected as a prior model.\ Depending on how close the reconstruction error of $A_k$ is to that of the most relevant $A_a$, a transfer method of choice can be selected, such as simply initializing the parameters and fine-tuning for low-related tasks, or more complicated methods like learning-without-forgetting \todo{citation needed} for highly related tasks.\\
At test time, the same mechanism is effectively employed to select the most relevant expert, with the addition of a softmax layer: a sample $x$ is fed through all auto-encoders and the softmax layer, comparing their reconstruction errors, and selecting the most likely expert.

The memory $M$ in \textcite{Sprechmann2018} stores key-value pairs $(f_\gamma(x_{train}),\, y_{train})$ obtained during training.\ At test time, a query $q$ is made by calculating the embedding $f_\gamma(x)$.\ Using $K$ nearest neighbors (KNN), a context $C$ is constructed.\ This context consists of the retrieved keys $h^{(x)}_k$, values $v^{(x)}_k$, and KNN weights $w^{(x)}_k$, for $k=1,\ldots,K$.\ An adaptation $\Delta_M$ is temporarily fine-tuned to minimize the weighted average negative log-likelihood over the context, i.e.: the parameters of output network $g_\theta$ are adjusted as to reduce the error for the similar examples in the context, thereby improving its prediction of the current sample.\ An important note to this is that the adaptations $\Delta_M$ are accumulated in $\Delta_{total}$ which is permanently added to the parameters, thus continually improving the network's performance throughout test time until $\Delta_M$ eventually diminishes.

In \textcite{Schwarz2018}, the knowledge base policy $\pi^{KB}$ informs an active learning policy during the so-called \emph{progress} phase.\ This transfer of knowledge is achieved through layer-wise connections: for a given layer $i$ in the active policy, activations $h_i$ are computed using the previous layer's activations $h_{i-1}$ and the activations of the corresponding knowledge base's layer $h^{KB}_{i-1}$.\ These knowledge base activations are first fed through an `adapter' in the form of a multi-layer perceptron so that the extent to which activations from $\pi^{KB}$ are added can be precisely fine-tuned during training, without altering $\pi^{KB}$ itself.

When an agent encounters a new environment $M_t$ in \textcite{Wang2022}, it first samples some transitions $(s, a, r, s')$ using a uniform behavior policy, ensuring broad exploration of the environment.\ These transitions are used to construct state-action pairs and reward-state pairs used as inputs $\bvec{X}_t$ and labels $\bvec{Y}_t$, respectively (\autoref{sec:KB}).\ The predictive likelihood $p_{\bvec{\vartheta}^{(l)}_t}(\bvec{Y}_t|\bvec{X}_t)$ is then calculated for each model $\bvec{\vartheta}^{(l)}_t$, measuring how well a model explains the observations.\ This way, the identity $l^*$ of the current environment is obtained.\ The policy parameters $\bvec{\theta}_t$ are then initialized as $\bvec{\theta}^{(l^*)}$, ready to be further fine-tuned.

In \textcite{Xie2021}, knowledge transfer happens by simply pretraining a policy on old replay buffers.\ The buffers of previous tasks $\mathcal{D}^{1:i-1}$ are restored into a buffer $\mathcal{D}^{\mathrm{src}}$ when training on a new task $\mathcal{T}^{i}$.\ However, these buffers are relabeled using the new reward function from the current environment\footnote{A key assumption of their method is that the reward functions of environments are either known beforehand, or are user-specified}.\ A sample $(\bvec{s, a, s'}, r)\in \mathcal{D}^j$ is thus relabeled as $(\bvec{s, a, s'}, r^i(\bvec{s, a}))$.\

The generative model and task solving model from \textcite{Shin2017} are combined into a module termed the \emph{Scholar}.\ Each task requires the training of a new \emph{Scholar}, which is informed by the \emph{Scholar} of the preceding task: Along with the input data $x$ and labels $y$ for the task at hand, the current task solving model also receives generated samples $x'$ from the old \emph{Generator}, labeled by outputs $y'$ from the corresponding old \emph{Solver}.


\section{Maintaining the Knowledge Base}\label{sec:KB-maintainance}
Maintaining the knowledge base can ensure that it remains informative.\ A knowledge base can be updated by adding new data points, by adapting existing data points, or - if applicable - updating a network or policy.\ Furthermore, these updates could be performed dynamically throughout the application's operational lifetime, or during separate phases only, e.g., updating the knowledge base during training and keeping it static at test time.

Of the previously discussed literature, both \textcite{Aljundi2016} and \textcite{Sprechmann2018} do not update their knowledge bases after training.\ \textcite{Sprechmann2018} mention that during training, a fixed budget memory is used, where the oldest data is replaced first, once capacity is reached.

In \textcite{Nguyen2011}, the linear independence test results in measure $\delta$, which is used to update the dictionary with fixe budget.\ To reiterate, the $\delta$ for a point $\bvec{d}_i$ measures its distance to the space spanned by all the points currently in the dictionary.\ Conversely, a smaller $\delta$ can be better approximated by the dictionary.\ If dictionary $\mathcal{D}$ is not yet at full budget, and the $\delta$ for a new point $\bvec{d}_i$ exceeds a certain predetermined threshold, the point should be added to the dictionary.\ However, when the dictionary is at full capacity, the new point is inserted in the dictionary, which is then re-evaluated to find and delete the now least informative point.\ Note that after any insertion or replacement of a dictionary point, \emph{all} points in $\mathcal{D}$ have to be evaluated for linear independence again, since adding or removing points changes the independence of other points as well.\todo{add forgetting factor or not relevant?}

The map in \textcite{Chatzilygeroudis2016} is constructed in simulation using MAP-elites.\ An empty $N$-dimensional grid map, spanned by the $N$ features of interest, is initiated.\ As a start, a certain number of behaviors are randomly generated and placed in the map according to their feature descriptors.\ In simulation, the performance measures (in this case, the \emph{Generic Reward}) of these \emph{solutions} are recorded and stored alongside the behaviors in the map.\ For all future iterations, the rest of the map is gradually filled in by selecting a solution in the map at random, and creating a modified version of it (e.g., by mutation or crossing-over multiple solutions).\ This modified version is placed in the map according to its features, and the performance is stored alongside it.\ Should a cell in the map already be occupied, then only the solution with the best performance is stored\footnote{In \textcite{Chatzilygeroudis2016}, the performance is actually a set of Gaussian processes that model the relative outcome of a behavior, but the authors do not specify on what basis solutions in identical cells of the map are replaced}.\ This process can repeat for a predetermined number of iterations, or until a solution with a certain satisfactory performance is obtained~\cite{Mouret2015}.\\
During deployment, when searching the map for a good behavior (\autoref{sec:retrieval}), the selected behavior and its result in the real world are recorded and used to update the Gaussian processes that function as performance measures in the map~\cite{Chatzilygeroudis2016}.

Updating policy $\pi^{KB}$ from \textcite{Schwarz2018} is done through knowledge distillation.\ At \emph{compression} time $t$, policy $\pi^{KB}_t$ is trained to produce outputs similar to active policy $\pi_t$ by minimizing the $KL$ loss\todo{citation needed} between their respective outputs.\ However, to make sure that previous knowledge is not forgotten, the loss function is expanded by a term that uses Elastic Weight Consolidation (EWC)\todo{citation needed}.\ This term essentially `punishes' large differences between the parameters $\theta^{KB}_t$ and $\theta^{KB}_{t-1}$.

In \textcite{Wang2022}, the library of environment parameters is updated incrementally.\ At each time $t$, the library might contain $L$ sets of parameters $\{\bvec{\theta}^{(l)}_t,\bvec{\vartheta}^{(l)}_t\}^L_{l=1}$ corresponding to environment clusters $M^{(l)}$.\ First, a new set $(\bvec{\theta}^{(L+1)}_t,\bvec{\vartheta}^{(L+1)}_t)$ is initialized to represent a potential new environment cluster.\ After gathering transitions and calculating (preliminary) predictive likelihoods of the models, posterior probabilities of model parameters w.r.t.\ transitions are calculated, i.e., $P(\bvec{\vartheta}^{(l)}_t|\bvec{X}{_t}, \bvec{Y}_t)$.\ However, the posterior for $\bvec{\vartheta}^{(L+1)}_t$ is actually calculated differently than for all $l\leq L$.\ The calculation is based on a Chinese restaurant process (CRP)\todo{citation needed}, where the probability of the environment cluster being added is considered in its evaluation on the transitions.\ Likewise, the posteriors of the models $\bvec{\vartheta}^{(l)}_t$ for $l\leq L$ are in turn calculated considering the number of models that have been assigned to their respective clusters.\ If the posterior of $\bvec{\vartheta}^{(L+1)}_t$ is more likely than for any $\bvec{\vartheta}^{(l)}_t$ (with $l\leq L$), the library is expanded with parameters $(\bvec{\theta}^{(L+1)}_t,\bvec{\vartheta}^{(L+1)}_t)$.\\
Expansion or not, all environment model parameters in the library are then updated to $\bvec{\vartheta}^{(l)}_{t+1}$ using the Expectation-Maximisation (EM) algorithm.\ This updated library is used as in \autoref{sec:retrieval} to identify the current environment.\ After fine-tuning the selected $\bvec{\theta}^{(l^*)}_t$, resulting in $\bvec{\theta}^*_t$, all policy parameters are updated to $\bvec{\theta}^{(l)}_{t+1}$, which effectively results in identical parameters except for $\bvec{\theta}^{(l^*)}_{t+1}$.

In \textcite{Xie2021}, for the online improvement of the pretrained policy, the agent stores its interactions with the environment in buffer $\mathcal{D}^i$.\ To update the policy parameters, the agent bases itself on a randomly sampled batch from $\mathcal{D}^{\mathrm{src}} \cup \mathcal{D}^i$.\ When the agent reaches a sufficient performance, $\mathcal{D}^{\mathrm{src}}$ can be discarded and $\mathcal{D}^i$ is saved somewhere (to be restored and relabeled for future tasks, \autoref{sec:retrieval}).

To transfer knowledge ``stored'' by old generative models in \textcite{Shin2017}, new \emph{Generators} are not only trained to imitate real input data from the task at hand, but also to imitate ``fake'' data produced by old models.\ The exact ratio at which real new samples and old fake samples are mixed is an important aspect that influences the rate at which new \emph{Scholars} will forget data from older models.
